# DEVELOPMENT.md

## Purpose
This document describes how to set up, build, and run `diagrammer` for development.

## Environment setup
1. Install Node.js 18 (or newer as supported by `package.json`).
2. From the repo root, run:
   - `npm install`
3. If you want the local web backend and all integrations, inspect `scripts/setup.sh` and run:
   - `scripts/setup.sh`
4. For a self-contained test environment:
   - `scripts/setup.sh SELFTEST`

## Build workflow
- Full build (Rust native binary, WebAssembly module, CLI, web UI):
  - `make all`
- Build Rust core parser & generators only:
  - `cargo build --release -p diagrammer-core`
- Build WebAssembly module only:
  - `make wasm_pkg`
- Build web UI assets:
  - `make web`
- Build test harness:
  - `make -C tests`
- Clean workspace:
  - `make clean`

## Runtime workflows
### Browser / Web UI
1. Start the local server:
   - `node web/miniserver.js 8777`
2. Open in a browser:
   - `http://localhost:8777/index.html`
3. The browser UI executes the 100% Rust core in-memory via client-side WebAssembly (`build/wasm/diagrammer_core_bg.wasm`), with zero backend roundtrip for parsing or generation (falling back to `/parse` if WebAssembly is unsupported).

### CLI usage
- Parse and transpile a diagram file:
  - `node js/generate.js tests/test_inputs/state.txt seqdiag`
- Visualize a diagram through the CLI:
  - `node js/t.js tests/test_inputs/state.txt dot output /tmp/output.png`
- If piping input:
  - `cat file.txt | node js/generate.js - seqdiag`

## Project structure
- `crates/diagrammer-core/` — 100% Rust core: Pest PEG grammar (`src/diagrammer.pest`), AST builder (`src/builder.rs`), and all 13 diagram generators (`src/generators/`)
- `build/wasm/` — WebAssembly package compiled from Rust core via `wasm-pack`
- `js/` — runtime CLI helpers, parser integration, and visualization support
- `web/` — browser editor (ACE), WebAssembly client integration, and web visualizations (D3, GoJS, Viz.js)
- `tests/` — language inputs, reference outputs, and browser Jest test suite
- `scripts/` — auxiliary build/test/export scripts

## Recommended development flow
1. `npm install`
2. `make all`
3. Edit code in `crates/diagrammer-core/`, `js/`, or `web/`
4. Run Rust unit & parity tests:
   - `cargo test --manifest-path crates/diagrammer-core/Cargo.toml`
5. Run a targeted CLI check:
   - `node js/generate.js tests/test_inputs/state_sequence.txt mscgen`
6. Run Jest browser tests:
   - `make -C tests jesttests`
   - `make -C tests jesttests`

## Notes for contributors
- `build/diagrammer_parser.js` is generated by `make all` / `make parser`.
- **Parser Backend Toggle**: By default, `make all` builds the original **Jison** parser. You can build with the Rust **Pest** shadow parser using `PARSER_BACKEND=pest make all` or toggle at runtime with `DIAGRAMMER_PARSER=pest node js/generate.js ...`.
- `tests/` contains both JS/TS test code and reference regression fixtures.
- Browser/web integration uses `web/miniserver.js` plus `web/visualizations` modules.
- Always run `make test` after grammar/parser changes to validate both text and image output.
